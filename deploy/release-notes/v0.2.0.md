t3opt v0.2.0 runs against a t3code with a big history. Plan 2 is in [the map issue](https://github.com/djosh34/t3-optimizations/issues/67); the sidecar changes are in [PR #87](https://github.com/djosh34/t3-optimizations/pull/87).

## What changed since v0.1.0

- The sidecar loads a thread when a phone opens it: t3's bounded snapshot first, then older pages. It no longer fetches the whole history at start.
- One cache for threads and images, 256 MB by default (`--cache-mb`). The least recently used thread goes first. Phones keep what they have.
- The newest 50 live threads go to phones ahead of time over an idle link (`--preload`, 0 turns it off).
- Phones' sync state keeps object bytes only until the phone stored them, in memory and on disk.
- Ids in object meta are hashed, so long delegated-task ids fit.
- On a clean link the sender ramps up faster, and after 2 s idle it restarts from 256 kB/s.
- `t3opt-sidecar-main.service` and `install.sh --main`: a second sidecar for the t3code already on the host (`~/.t3`, port 3773), on `https://<host>:14443`, with `MemoryMax=768M`.

On the owner's t3code (about 1,200 threads, 3 GB), the sidecar peaked at 233 MB RSS with one phone and 330 MB with two phones each opening 30 threads, with no OOM kill.

Phones on the v0.1.0 app show empty threads until they tap "Update ready, reload": the new app reads hashed meta.

## What is in it

- `t3opt-sidecar-linux-x86_64`, `t3opt-sidecar-linux-arm64`: the sidecar, static binaries.
- `t3opt-web.tar.gz`: the home-screen web app (the t3code v0.1.7 web client with the t3opt adapter), served by the sidecar.
- `t3opt-server.service`, `t3opt-sidecar.service`: the plan-1 pair. `t3opt-server` runs the stock t3 v0.1.7 release with its own data in `~/.t3opt`, on localhost only; the sidecar is its client.
- `t3opt-sidecar-main.service`: the sidecar for the host's own t3code, installed only with `--main`.
- `install.sh`, and `SHA256SUMS` of every file.

## Install

On a Linux host on a tailnet, as the user who runs the services:

```sh
curl -fsSLO https://github.com/djosh34/t3-optimizations/releases/download/v0.2.0/install.sh
T3OPT_RELEASE=v0.2.0 bash install.sh          # the plan-1 pair on 12443
T3OPT_RELEASE=v0.2.0 bash install.sh --main   # also the main sidecar on 14443
```

It leaves the official t3code service and every other route alone. With `--main`, the only thing added to `~/.t3` is the main sidecar's login session, and one for each paired phone. Pair a phone with a code from `~/.local/share/t3opt/t3-0.1.7/t3 pair --base-dir ~/.t3opt` (12443) or `--base-dir ~/.t3` (14443).

[deploy/README.md](https://github.com/djosh34/t3-optimizations/blob/v0.2.0/deploy/README.md) has the details: paths, pairing, how to stop and remove it, and the live checks.
